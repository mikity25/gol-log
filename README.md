## 1. サービス概要


**どんなサービスか**

行ったゴルフ場の「自分視点の本音メモ（難易度・食事・設備）」をボタンタップ中心でサクッと記録し、自分の過去スコアや体験と一緒に直感的に見返せる自分専用のゴルフ場カルテサービス。

**誰の、どんな課題を、どう解決するか**

コース選びで失敗したくないゴルファーが、大手予約サイト等の「他人の口コミ」ではなく、自分自身のリアルな体感（難易度・費用・食事満足度）を負担なく蓄積し、次の最適なコース選びや友人への推薦に迷わず活かせるようになる。


---


## 2. 開発背景


### 2-1. きっかけ（ゴルフを愛するからこその悩み）

大好きなゴルフラウンドですが、1ラウンドの費用も時間も決して安くはありません。だからこそ「1回1回のラウンドを大切にしたい」という強い思いがあります。ゴルファーにとってのコース選びは、楽しみでありとても重要です。

しかし、過去に行ったコースが増えるにつれ、記憶やGoogleマップの保存機能だけでは「なぜ保存したのか」「コースの難易度や食事、接客はどうだったか」を忘れてしまうことが頻繁にありました。

また、友人から「おすすめのゴルフ場教えて！」と聞かれた際にも、記憶を辿りながらLINEでつらつらと長文を打って伝えており、共有に時間がかかって効率が悪いことにもどかしさを感じていました。


### 2-2. 既存サービスへの違和感と「自分基準」へのこだわり

**他人の評価と自分の感覚のズレ**
予約サイト（楽天GORA等）の口コミはあくまで「他人の意見」であり、自分が実際にどう感じたか（難易度・食事・接客など）とはギャップがありました。

**スコア管理アプリの限界**
既存のスコア管理アプリは「全体の平均スコア」などが中心で、各コースごとの詳細な体験や「スコアが良いコース順のランキング」などを直感的に振り返るには不十分だと感じていました。

**「手軽さ」と「自分基準」の両立**
体験データを次回のリベンジやコース選びに活かしたいものの、毎回長文メモを残すのは面倒です。だからこそ「ボタンタップでサクッと記録でき、自分基準で振り返れる簡便なカルテ」の必要性を痛感しました。

## 3. 課題の整理


### 3-1. 表に見えている困りごと

* 過去に行ったゴルフ場の印象（コースの難易度・食事・お風呂・接客など）や実際の支払金額、スコアを忘れてしまい、次のゴルフ場選びやリベンジに活かせない。
* ラウンド後に自分の振り返りや分析を楽しんでする習慣が持てず、次のプレイに向けた「コースマネジメント思考」が身につきにくい。


### 3-2. 本当に解決したい課題は何か

* なぜ手元のメモやスマホでは困るのか？
Googleマップや標準メモ帳では、ゴルフ特有の評価項目（難易度・クラブハウス設備・支払額など）を構造化して記録・検索できず、振り返りや記録の習慣化もしにくいため。

* なぜ既存の予約・スコア管理アプリではダメなのか？
大手スコア管理アプリ等は機能が多すぎて複雑であり、メインはあくまで「予約・総合スコア・詳細なショット分析」であること。また、既存の口コミサイトも「一般公開」が前提のため、自分が感じたリアルな本音（設備や接客への不満等）を自由に書くことができないため。

* なぜ自由に書けないと困るのか？
一般公開前提の口コミサイトでは、他人の目を気にして「設備が古い」「接客が微妙だった」といった本音を書きづらい。しかし、次のコース選びで失敗しないためには、自分が感じたリアルな不満点も含めて記録しておく必要がある。そのため、誰にも見られない自分専用の非公開カルテが必要。


**本当に解決したい課題**
多機能すぎるツールや他人の目を気にすることなく、自分の感覚に合った「自分専用のゴルフ場カルテ」を気軽に蓄積し、次のラウンドやコース選びに活かせる振り返り環境がないこと。

## 4. 想定ユーザーについて


### 4-1. 想定しているユーザー

* メインターゲット:
月1〜2回ゴルフを楽しむ30代前半アマチュア女性ゴルファー。1ラウンドの時間や費用を大切にしたい反面、過去に行ったコースの印象（難易度・食事・設備）を忘れがちで、次のコース選びで失敗したくない人。

* 月1〜2回ペースでラウンドに行くが、過去に行ったコースの詳細や評価を忘れてしまう
* 既存の口コミサイトは他人の意見ばかりで、自分の感覚（難易度や食事の好み）とズレがあると感じている
* ゴルフ友達からおすすめを聞かれた際、思い出してLINE等で長文を打って伝えるのが面倒で効率が悪いと感じている
* プレー後に細かく長文で記録を残すのは面倒だが、自分基準のデータは手軽にストックしたい
* 既存のスコア管理アプリは機能が複雑すぎて、コースや設備の振り返りには使いにくいと感じている


### 4-2. 自分とユーザーの距離

* 選んだもの：自分自身
* 理由：自分自身がゴルフ場に行った際、「このコースの難易度やランチの印象を自分基準でメモしておきたい」と強く感じた実体験に基づいているため。


### 4-3. 実際に使われる可能性について（需要・存在確認）

* まず最初に使ってくれそうな人は誰か：
自分自身、およびゴルフが趣味の家族・友人・知人

* その人は、どんな場面でこのアプリを思い出すか：
ゴルフが終わった直後の記録したい時、次のゴルフ場予約を検討している見返したい時

* 今の生活の中で、代わりに使っているものは何か：
自分の記憶、楽天ゴルフスコア管理アプリ、Googleマップの保存機能

* それを置き換えてまで使う理由はあるか：
既存ツールでは「ゴルフ専用の評価項目（難易度・食事・お風呂等）」をボタンで記録できず検索・ソートもできないが、本アプリであれば簡単に記録でき、スコアや条件別に一覧検索できる。


### 4-4. ユーザーがサービスを導入して利用するまでのイメージ（導入・継続の流れ）

* どんな場面・困りごとがきっかけで、このサービスを知る・思い出すか：
ゴルフ後のスコアや体験の整理時、または過去に行ったコースを振り返りたくなった時

* 最初の一歩（登録・導入）で、ユーザーは何をする必要があるか：
会員登録後、直近行ったゴルフ場名を入力し、評価ボタンをタップして1件目のカルテを作成すること

* 利用を続ける理由は何か：
入力がボタン中心で手間がかからずプレー後でも登録しやすいこと、および蓄積された「自分だけのゴルフ図鑑」が次のコース選びに直接役立つため。

## 5. 既存サービス・競合調査


### 5-1. 似たサービスの調査

* サービス名:楽天ゴルフスコア（楽天のスコア管理・分析）
* URL: https://gora.golf.rakuten.co.jp/doc/guide/gora_app/score/
* 機能: コースごとのスコア管理・分析・共有、ショットコンパス、GPSコースマップ、高低差計測、スイング解析、チェックイン、スマートウォッチ連携、予約情報連携。


### 5-2. それでも自分が作りたい理由

* 既存アプリはスコア情報の記録が中心であり、「なぜまた行きたいと思ったのか」「コースや設備のどこが自分に合っていたか・微妙だったか」という自分視点の本音カルテを残して見返せないため。
* スコア管理以外にも高機能な仕様が多く画面が複雑なため、ゴルフ初心者や女性、シニア層にとっては操作が難しく使いづらいため。
* 一般公開前提の口コミサイトでは他人に気を遣って本音を書けないため、自分だけの非公開プライベート領域で自由な評価を管理したかったため。


### 5-3. 差別化を「体験価値」で表現する

* 疲れたラウンド直後でも一瞬で記録:
文字入力をほとんどせずに「ボタンタップだけ」で、自分基準の満足度・難易度・費用をサクッとカルテ化できる（長文入力のストレスなし・移動中に完結できる体験）

* 自分基準の比較・即時共有:
大手の平均評価ではなく「自分の感覚にぴったり合ったコース」を一瞬で並び替えられ、友人へのコース推薦時にも自分のリアルな評価を迷わずスムーズに共有できる。

* 迷わせないシンプルなUI:
多機能すぎて複雑な既存アプリとは異なり、無駄を削ぎ落とした視認性の高いUIにより、ゴルフ初心者からシニア層まであらゆるユーザーが直感的に使いこなせる。

## 6. このサービスで提供したい価値


### 6-1. ユーザーの変化

* 行動の変化:
ラウンド中や終了後に長文メモやスコア集計をするストレスがなくなり、わずかな隙間に「ボタンタップ数回」で体験（難易度・設備・食事等）をサクッと記録・整理する習慣が身につく。また、次のコース選びや友人へのコース提案の際に、過去の自分のカルテを一瞬で検索・並び替えて選定・共有できるようになる。

* 気持ちの変化:
大手サイトの全体評価や他人の口コミに左右されず、「自分自身がどう感じたか」を基準とした納得感のあるコース選択やラウンド事前準備ができるようになり、不安やストレスが解消される。

* 考え方の変化:
ゴルフ場を単なる「今日のプレイ場所」として捉えるのではなく、「自分の好みや成長に合ったコースを図鑑のように蓄積・比較していくコレクション対象」として捉えられるようになる。視野が広がる。


### 6-2. 価値を一文で表す

ゴルファーが、自分だけの評価や体験ログをサクッと蓄積し、コースごとに振り返りができる個人向けゴルフ場カルテ。

## 7. このアプリで実現すること


### 7-1. MVPで作る機能

* 会員登録・ログイン機能:
自分専用の非公開カルテとしてデータを保持・管理するためのユーザー認証機能。

* ゴルフ場カルテの登録・編集・削除機能:
ゴルフ場名、ラウンド日、総スコア、満足度、難易度、食事、設備等の評価をボタンタップ中心で手軽に記録・更新できる機能。
**満足度・難易度・食事・設備等の評価は、ボタンタップ（ラジオボタンやenum）で入力できるようにする。**
例:
- 満足度: ⭐️⭐️⭐️⭐️⭐️（5段階評価）
- 難易度: 😎 簡単 / 🥱 普通 / 😅 やや難 / 😰 難しい
- 食事: 👍 美味しい / 👌 普通 / 👎 微妙
**ゴルフ場名は、数値入力・文字入力が必要だが、入力項目を最小限に抑える。**
**同じゴルフ場に複数回訪問した場合、訪問日ごとにカルテを作成する。**
（MVPでは「記録のハードルを下げる」ことを最優先にし、複数回の訪問履歴を一覧で見やすく表示する機能は本リリースで実装する。）
**9ホールと18ホールのスコアをそれぞれ入力できるようにする。**

* カルテの一覧・詳細表示機能:
登録したゴルフ場カルテを一覧で確認し、個別の評価内容をサクッと振り返ることができる機能。


### 7-2. 本リリースで作る機能

* お問い合わせ機能:
ユーザーからのご意見・不具合報告を受け付けるフォーム機能。

* 評価順・条件別の並び替え（ソート）・検索機能:
自分のつけた満足度や難易度、ゴルフ場名でカルテを検索・並び替えて、コース比較に活用できる機能。
9ホールと18ホールのスコアを混在させてもソート時に正しく並び替えられるよう、18ホール換算スコアを自動計算して保存する機能も追加する。

* ゴルフ場訪問履歴の可視化機能:
MVPでは「同じゴルフ場に複数回訪問した場合、訪問日ごとにカルテが作成される」仕様だが、本リリースでは「同じゴルフ場の過去の訪問記録を時系列で一覧表示し、スコアの推移や評価の変化を確認できる機能」を追加予定。

* 画像保存機能（写真アップロード）:
コースの風景やランチの写真などを1〜2枚保存できる機能。

* ゴルフ場情報の自動入力サポート（外部API連携）:
ゴルフ場名入力時に候補を表示し、正確な名称や住所を自動で補完・取得する機能。

* プレー条件のアイコン表示機能:
一覧画面・詳細画面で、プレー条件（平日/土日祝、18H/9H、通常/スルー、食事つき/なし、セルフ/キャディつき）をアイコンで直感的に識別できるようにする機能。

* 費用データの記録補助機能:
プレイ料金（平日/祝日）や、キャンセル規定などの入力項目を追加し、より詳細な体験ログとして蓄積できる機能。

* カルテの簡単共有機能（URL・LINE共有）:
自分のカルテ（または特定のコース評価）を友人やグループに手軽に共有できる機能。

## 8. 懸念点とその対策


### 懸念点①
* 何が問題になりそうか：
ラウンド後の記録作業が面倒で離脱するリスク
* なぜそう思うか：
プレー中や後は体力を消耗しており、長文を入力するハードルは非常に高いため。
* そのために考えている対策：
必須入力項目を「ゴルフ場名」「ラウンド日」「満足度」の3つのみに絞る
スコア・難易度・食事・設備はすべて任意項目とし、「まずは満足度だけでも保存できる」手軽さを最優先にする
初回登録時に「過去に行ったお気に入りコースをまずは1件登録してみよう」という誘導UIを配置する


### 懸念点②
* 何が問題になりそうか：
使い始めはデータ数が少なく価値を感じにくい
* なぜそう思うか：
「自分だけのカルテを蓄積・検索できる」ことが本アプリの強みであるため、1〜2件しか登録がない初期段階ではアプリの本当の便利さが伝わりづらい。
* そのために考えている対策：
初回登録時に「過去に行ったお気に入りコースをまずは1件登録してみよう」という誘導UIを配置し、1件目の作成をスムーズに促す。


### 懸念点③
* 何が問題になりそうか：
ユーザーごとにゴルフ場の名称入力（正式名称、略称、ひらがな表記など）がばらつき、一覧表示や検索時に見づらくなる。特に、同じゴルフ場に複数回訪問した場合、表記揺れによって別のゴルフ場として扱われてしまい、訪問履歴の集計や比較が困難になる。
* なぜそう思うか：
MVP段階では外部API連携を外して手動入力を想定しているため、表記揺れが発生しやすい。同じゴルフ場でも「◯◯ゴルフクラブ」「◯◯GC」「◯◯ゴルフ場」など、入力のたびに表記が変わる可能性がある。
* そのために考えている対策：
MVPの段階では「自分で分かればOK」というプライベートカルテの割り切りを持たせつつ、本リリースでゴルフ場自動補完機能（外部API連携等）による自動補完を実装して根本解決する。

## 9. 今後の展開・発展の方向性

* 入力補助・自動補完（Google Places API連携）:
ゴルフ場名の検索・自動入力機能を補強し、表記揺れをなくすとともに登録の手間をさらに軽減する。

* ビジュアル・タグ識別表示の強化:
プレー条件（平日/土日祝、スルー/通常、食事付き等）をアイコンタグで直感的に一覧表示し、ひと目で過去の体験条件を把握できるようにする。

* 地図・スタンプラリー表示（Google Maps API連携）:
訪問したゴルフ場をマイマップ上にピン留め・視覚化し、全国の制覇率や訪問実績をスタンプラリー感覚で楽しく振り返れる仕組みを導入する。

* AI分析・傾向アドバイス（OpenAI API連携）:
蓄積されたカルテやスコアデータから「得意なコース傾向（グリーンや距離感など）」や「苦手なコースの共通点」を自動分析し、次のコース選びのアドバイスを提供する機能を追加する。

* 入力項目のカスタマイズ機能:
「キャディの有無は使わない」「練習場の有無を追加したい」など、ユーザーのプレイスタンスに合わせた入力項目の表示・非表示を設定可能にし見やすくする。

* シンプルで直感的なUI/UXの維持・追求：
今後どのような機能を追加・拡張する場合であっても、「画面をごちゃごちゃさせない」「ボタンタップ中心で迷わず使える」という本アプリ最大の強みを徹底し、あらゆるゴルファーがストレスなく使い続けられるシンプルな操作感を維持する。


###　検討したが見送った機能

* 自給自足型フォーム（過去の登録リストからプルダウン選択）:
「表記揺れを防ぐ」という点で有効だが、MVPでは手入力のみとし、本リリースで外部API連携による自動補完を実装することで根本解決する方針としたため見送った。

* カルテの公開・非公開切り替え機能:
「公開したい人もいるのでは」という視点で検討したが、本アプリのコアバリューは「他人に気を遣わず本音を書ける自分専用カルテ」であるため、公開機能を入れることでそのコンセプトがブレてしまうと判断し見送った。

* 「みんなの口コミ」閲覧機能:
「他人の評価も参考にしたい人がいるのでは」という視点で検討したが、既存の課題である「他人の意見とのズレ」「自分の感覚を基準にしたい」という本質的な解決から外れるため見送った。

## 10. 技術スタック


### 10-1. 使用予定の技術

**バックエンド**: Ruby on Rails 8.0
カリキュラムで学習した技術を活かし、機能実装に集中できるため

**フロントエンド**: ERB / HTML / CSS / JavaScript / Tailwind CSS
シンプルなUIで十分なため、React などは使わずに ERB で実装する。Tailwind CSS でスタイリングを効率化

**データベース**: PostgreSQL
Renderでのデプロイに対応しており、Rails との相性も良いため

**デプロイ先**: Render
無料枠で Rails アプリをデプロイでき、設定がシンプルなため

**今回チャレンジしたい点：**
* ボタンタップ中心（enumやラジオボタン）で入力ストレスを極限まで減らしたUI/UX設計
* MVPでは9ホールと18ホールのスコアをそれぞれ入力できるようにし、本リリースで18ホール換算スコアを自動計算する機能を追加する

**不安な点とその対策：**
外部APIの導入や複雑な機能追加により、開発工数が増加して目標期日に遅れるリスクがあること。
対策として、まずはRailsの標準機能のみを用いたシンプルな手入力フォームでMVPを最速リリースし、外部APIや高度なソート機能等は本リリース以降に段階的に実装すること。

### テーブル詳細

* **users テーブル（ユーザー情報）**

| カラム名 | データ型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | bigint | PRIMARY KEY | ユーザーID |
| name | string | - | ユーザー名（任意、マイページ表示用） |
| email | string | NOT NULL, UNIQUE | メールアドレス（ログイン用） |
| encrypted_password | string | NOT NULL | パスワード（Devise管理） |
| created_at | datetime | NOT NULL | 作成日時 |
| updated_at | datetime | NOT NULL | 更新日時 |

* **records テーブル（ゴルフカルテ）**

| カラム名 | データ型 | 制約 | 説明 |
| --- | --- | --- | --- |
| id | bigint | PRIMARY KEY | カルテID |
| user_id | bigint | NOT NULL, FOREIGN KEY | 作成者のユーザーID |
| golf_course_name | string | NOT NULL | ゴルフ場名 |
| played_on | date | NOT NULL | プレー日 |
| satisfaction | integer | NOT NULL | 満足度（enum: star1〜star5） |
| difficulty | integer | - | 難易度（任意） |
| food | integer | - | 食事の評価（任意） |
| facility | integer | - | 設備の評価（任意） |
| score_18h | integer | - | 18ホールのスコア（任意） |
| score_9h | integer | - | 9ホールのスコア（任意） |
| converted_score_18h| integer | - | 18ホール換算スコア（自動計算、任意） |
| memo | text | - | 自由記述メモ（任意） |
| created_at | datetime | NOT NULL | 作成日時 |
| updated_at | datetime | NOT NULL | 更新日時 |
